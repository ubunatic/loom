Why loom

Command line tools need selection, editing, and layout without losing the surrounding shell context. Extracted from uzu, loom gives independent tools shared input and rendering behavior, with terminal restoration treated as part of the interface.

What it does

Reusable widgets

Choice, Table, Confirm, TextInput, TextArea, Settings, Pane, and Canvas provide selection, editing, layout, and rendering primitives.

Declarative layouts

YAML describes widget trees and layouts. Example applications and the loom-demo gallery make the library’s behavior inspectable.

Rich terminal editing

RichTextEdit supports styled spans, pills, clipboard and undo/redo, formatting popovers, and box-aware selection and drawing.

Current scope and limits

The API is pre-1.0 and may change. Real terminal behavior needs live checks alongside unit tests. The README’s older release status is tracked separately; the October 4 story records v0.3.0.
