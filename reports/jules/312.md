## Verdict
still valid. `RichDocument` holds only plain `RichLine`s, so `ToMarkup` writes rendered glyphs and the original tag source is lost when a `.tui` file is saved.

## Evidence
- `ParseMarkup` draws `[box]`, `[table]` and `[image]` blocks into plain `RichLine`s at parse time:
  - `markup.go:76`: `func ParseMarkup(src string) (*RichDocument, error) {` returns a document populated by calls like `box.render()` and `table.render()`.
  - `markup_box.go:84`: `func (b *markupBox) render() []RichLine {` draws the border box.
  - `markup_table.go:219`: `func (t *markupTable) render() []RichLine {` draws the table and its separators.
  - `markup_image.go:130`: `func renderMarkupImage(img MarkupImage, opts MarkupOptions) ([]RichLine, error) {` draws the image lines.
- `RichDocument` keeps no block structure:
  - `richtext.go:13`: `type RichDocument struct {` only contains a slice of `RichLine`s.
- `ToMarkup` writes the drawn glyphs instead of the block tags:
  - `markup.go:348`: `func (d RichDocument) ToMarkup() string {` loops over lines and spans, writing styled text with tags like `[style]text[/]`, not `[box]` or `[image]`.
- Accepted as a known limit in issue 311 §2.4 and `docs/TuiMarkup.md`:
  - `docs/TuiMarkup.md:90`: `ParseMarkup draws the box into plain lines, so a RichDocument holds no box`
  - `docs/TuiMarkup.md:146`: `draws plain lines and ToMarkup writes the drawn characters.`

Commands run: `grep -Rn "type RichDocument"` found `richtext.go:13`, `grep -Rn "func (.*) ToMarkup"` found `markup.go:348`, `grep -n "ParseMarkup" markup.go` found `markup.go:76`, `grep -n "func (.*) render" markup_*.go` found `markup_box.go:84`, `markup_table.go:219` and `markup_image.go:130`. `grep -i "draws the box into plain lines" docs/TuiMarkup.md` found `docs/TuiMarkup.md:90`.

## Smallest next step
Update `RichDocument` in `richtext.go` to optionally store a syntax tree or block metadata alongside `RichLine`s, so `ToMarkup` in `markup.go` can emit the original `[box]`, `[table]`, or `[image]` tags instead of the rendered border/image glyphs when block source is available. Alternatively, add block AST nodes to the document model instead of rendering them immediately during `ParseMarkup`.
