## 1. `diff --find` loop can increment cellX out of bounds

* **Citation:** `cmd/loom/diff.go:150`
* **Change:** Add a bounds check `if cellX >= buf.Cols() { ok = false; break }` before accessing the buffer element.
* **Why it helps:** Prevents an out-of-bounds panic when `measure.RuneWidth(r)` causes `cellX` to increment beyond the buffer boundary `buf.Cols()`. I verified this panic doesn't trigger with simple text, but if unprintable characters mismatch `StringWidth` the panic is possible because the outer loop boundary `x+measure.StringWidth(text) > buf.Cols()` is bypassed.
* **Smallest step:** Insert `if cellX >= buf.Cols() { ok = false; break }` inside the `for _, r := range needle` loop before calling `buf.Get(cellX, y)`.

## 2. `trimLine` fails to remove spaces before non-SGR sequences

* **Citation:** `cmd/loom/format.go:85`
* **Change:** Extend `trimLine` to ignore other common ANSI sequences before trimming trailing space, rather than just stripping space before sequences ending in `m` (SGR).
* **Why it helps:** Given ANSI inputs containing non-SGR sequences (like cursor moves, `\x1b[A`) at the end of a line, `format --trim-trailing` fails to remove trailing spaces preceding them, as the backward loop `s[start-1] == 'm'` immediately aborts. I verified this via `./loom format <(echo -ne " \x1b[A\n") --trim-trailing` which retains the space.
* **Smallest step:** Use `stripANSI` or a robust regex to identify trailing escape codes generally, and split them from the line body before executing `strings.TrimRight(body, " \t")`.

## 3. `view --plain` output adds an extra newline

* **Citation:** `cmd/loom/main.go:367`
* **Change:** Use `fmt.Fprint(cmd.OutOrStdout(), buf.PlainText())` instead of `fmt.Fprintln`.
* **Why it helps:** `buf.PlainText()` already includes newlines separating the rows. Using `Fprintln` appends a second newline to the output, adding an unexpected trailing blank line in plain output. I verified this using `loom view --plain` on a single-line input via `od -c` showing a trailing `\n\n`.
* **Smallest step:** Change `fmt.Fprintln(cmd.OutOrStdout(), buf.PlainText())` to `fmt.Fprint(cmd.OutOrStdout(), buf.PlainText())` in `viewCommand`.

## 4. `eval` annotation misses out of bounds lines

* **Citation:** `cmd/loom/main.go:309`
* **Change:** Print any diagnostics attached to rows beyond the parsed grid, or ensure `grid` matches the original `lines` count by padding it.
* **Why it helps:** The loop `for i, diagnostic := range diagnostics` appends to `byRow[diagnostic.row]`. `diagnostics` is generated by iterating over `lines` (split from the original text), while `grid` is generated by splitting `buffer.PlainText()`. `buffer.PlainText()` strips empty trailing lines. Thus, a diagnostic on a trailing line gets associated with a row that does not exist in `grid`, causing the diagnostic indicator to be silently dropped during the `for row, line := range grid` loop.
* **Smallest step:** Pad `grid` with empty strings up to the original `lines` count before iterating over `grid` in `writeAnnotated`, or print remaining diagnostics outside the grid loop.

## 5. `format --write` attempts to write temp file to `/dev/fd/` on piped inputs

* **Citation:** `cmd/loom/format.go:211`
* **Change:** Add a check `info.Mode().IsRegular()` before attempting to write atomically.
* **Why it helps:** Running `loom format <(echo "a") --write` fails with `open /dev/fd/.loom-format-...: no such file or directory` because `filepath.Dir("/dev/fd/63")` attempts to create a temp file in `/dev/fd`, which fails or is inappropriate. Atomic writes are for regular files only.
* **Smallest step:** Return an error if `--write` is used with a non-regular file, using `os.Stat(path)` and `!info.Mode().IsRegular()`.
