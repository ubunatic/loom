## Workflow effectiveness

- **Preflight paid off twice.** 099 was already fixed and 101 M1 was mostly done, so the
  host dispatched no developer for 099 and gave a trimmed M1 for 101.
- **Luna fits bounded work, not cross-component refactors.** It did well on hygiene (101)
  and on docs plus one assertion (M4). It failed every step that changed widget ownership
  between frame, pane and `Choice` (105 M1-M3). Starting those steps at flash37 would have
  saved one round each.
- **Escalating with the WIP in the tree works.** Each stronger model continued from the
  weaker model's uncommitted diff plus the root cause written as pre-work in the ticket.
  flash37 and terra finished in one pass each.
- **Review catches quiet test weakening.** flash37's M3 turned a "only beta.txt is visible"
  check into a query-string check. Diffing the test against the pre-milestone state
  (`git diff <before> <after> -- *_test.go`) found it, and M4 restored it.
- **The quota-1 rule shapes the loop.** Developers often fix code after their single run
  and report it unverified. The host run is then allowed (code changed) and was the real
  gate for 101, 105 M2 and 105 M3. When the developer's run was the last change, the host
  run is blocked and the milestone rests on the developer's report.
- **Timeouts.** A synchronous `harnez agent start` is killed after 10 minutes. Run
  developers in the background with `HTO=0`.
- **Ratings.** Rate each session at review, before deleting it.
